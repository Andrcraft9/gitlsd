# Contributing

This document defines general project workflow guidelines for both people and agents.

## Commits

- Treat each commit as a small project iteration that should not break anything.
- Keep each commit minimal and focused on one logical change.
- Split large changes into multiple commits when that makes the history easier to review or revert.
- Use a concise commit subject.
- Keep commit description lines at 80 characters or fewer.
- Use the commit description to explain important details, context, or tradeoffs behind the change.

## Documentation

- Update documentation when a change affects project behavior, usage, setup, architecture, or workflow.
- Keep `README.md`, `ARCHITECTURE.md`, `AGENTS.md`, `CONTRIBUTING.md`, and other relevant docs consistent with the code.
